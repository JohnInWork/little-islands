# DNG Codex — инструкция следующей модели

Всегда отвечай Ивану по-русски, о себе в женском роде. Сначала короткий план, затем
правки. Не спрашивай подтверждение на каждый локальный шаг. Покупки, push и
публикация требуют явного разрешения. Существующие изменения принадлежат Ивану;
сохраняй чужую работу и не откатывай её.

## Начни с нужного

1. [docs/START-HERE.md](docs/START-HERE.md) — текущая игра и карта модулей.
2. [docs/EXTENDING.md](docs/EXTENDING.md) — рецепт конкретного изменения.
3. [docs/NEXT-TASKS.md](docs/NEXT-TASKS.md) — небольшие следующие задачи и приёмка.

Рабочий проект содержит только **2D DNG Codex**. Вход:
`index.html` перенаправляет на `tools/dcss.html`; адаптер игры —
`tools/dcss.js`. Название репозитория `little-islands` оставлено для совместимости
GitHub URL. Не восстанавливай старый островной прототип как активную игру.

## Неподвижные требования

- Мобильная пиксельная roguelike/RPG на DCSS-тайлах, один гибридный герой.
- Тап по разведанному полу, экранный крест-стик и WASD задают движение; бой и
  подбор автоматические. Меню ставит симуляцию на паузу.
- Простое управление, глубина через экипировку, навыки, окружение и исследование.
- Крупный пиксельный UI без тонкого орнамента/blur; sans-serif и RU/EN для всех
  новых строк. Направление: [docs/2D-UI-DIRECTION.md](docs/2D-UI-DIRECTION.md).
- Сохранять реальные объёмные стены, свет и тени: `tools/dcss-rpg-world3d.js`
  и зависимость Three.js обслуживают текущую 2D-сцену. Это не удаляемая старая игра.
- Все носимые слои берутся из экипировки, а не декоративной «одежды по умолчанию».
- Каталог навыков не равен реализованным способностям. Неподключённые действия
  скрыты, эффекты интерфейса должны совпадать с эффектами в игре.

## Границы изменений

- Pure-модули `tools/dcss-rpg-*.js` с данными/правилами/генерацией/сохранениями не
  импортируют DOM, renderer, Three.js или звук. Визуальные адаптеры — исключение
  по назначению, например `dcss-rpg-world3d.js`.
- Игровые ID, seeded RNG, schema/generator/content versions — контракты.
  Не переименовывать ID и не менять порядок случайных вызовов ради оформления.
- Команда сначала валидирует цель, стоимость и состояние; затем применяется
  целиком либо отклоняется. Renderer не выдаёт опыт, очки, вещи или урон.
- Числа для боя/HUD/карточек берутся из общих правил. Состояние навыков и
  контракт подключения: [docs/2D-SKILLS-FOUNDATION.md](docs/2D-SKILLS-FOUNDATION.md).
- Новое сохраняемое поле требует явной миграции и проверок старых/повреждённых
  данных. Язык не меняет seed, здоровье, UID и неизвестные свойства.
- Будущая сеть: стабильные ID, явные намерения, детерминированные правила;
  транспорт и сервер сейчас не реализованы. Не объявлять существующий цикл
  fixed-step lockstep/replay engine.
- Не добавлять framework, ECS, глобальную шину событий или массовый рефакторинг
  без конкретного работающего потребителя.
- Асинхронные загрузки и dispose должны уважать владельца сцены и общий кэш.

## Проверка и передача

`npm ci` при необходимости установки зависимостей; затем **`npm run check`**
(unit/integration tests + production build). Сначала проверь целевой сценарий,
потом общий шлюз. Не обновляй expected автоматически, чтобы скрыть регрессию.

Новые механики проверяй чистыми правилами и реальным действием в браузере.
Для визуала/ввода/UI — 390×844 и 844×390, RU/EN, пауза, reload, клавиатурный фокус.
Браузер на компьютере не заменяет проверку настоящего телефона или FPS на нём.

Используй отдельный QA origin; не стирай localStorage пользователя и не
останавливай его dev-сервер. Закрывай только свои временные вкладки/сессии.

В финале: что теперь работает, что проверено, что остаётся. Не обещай публикацию,
полную совместимость NetHack или готовность всех навыков без фактов.
Обновляй статус системы в документации вместе с кодом.
