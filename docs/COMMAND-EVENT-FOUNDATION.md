# DNG Codex — локальные команды и события

Это узкая рабочая основа, а не готовый сетевой движок. Сейчас через неё полностью
проходят survival-срез, книги, контейнеры сундуков и торговые транзакции.

## Контракт

`createGameCommand()` получает `streamId`, монотонный `sequence`, тип, актёра,
цель и сериализуемый payload. Save v34 хранит следующий номер в
`run.commandSequence`. ID команды выводится только из потока и номера; язык,
анимация и частота кадров на него не влияют.

Чистая доменная функция возвращает один из результатов:

```js
{ ok: true, commandId, state, events }
{ ok: false, commandId, reason, events: [] }
```

Она сначала проверяет команду и всё входное состояние, затем строит новый state,
не мутируя аргументы. События получают ID `command.id:event:index`. Runtime может
показать частицы, звук или toast только после `ok: true`; визуал не выдаёт лут и
не решает исход боя.

## Как расширять

1. Добавить тип в доменный модуль, а не switch в HTML/renderer.
2. Передать только минимальный срез состояния, нужный правилу.
3. При расходе/выдаче стеков использовать `transactStackItems()` или аналогичную
   атомарную транзакцию.
4. Событие описывает свершившийся факт и содержит только сериализуемые данные.
5. Адаптер применяет возвращённый state один раз и затем проигрывает events.
6. Новое сохраняемое поле требует версии, миграции и corrupt-теста.

`tools/dcss-rpg-books.js` использует тот же конверт для `read-book`: чистая
команда возвращает `book-read` и результат изменения ранга либо пустой книги,
а runtime только расходует подтверждённый предмет и показывает отклик.

`tools/dcss-rpg-merchant.js` обрабатывает `merchant-buy`, `merchant-sell` и
`merchant-buyback`. Правило атомарно переносит золото и владение UID между
игроком и конкретным NPC; runtime только обновляет окно и проигрывает событие.

Не добавлять абстрактную глобальную шину без работающего потребителя. Следующий
полезный перенос — одна дверная команда целиком, затем одна завершённая атака.
Дедупликация, event log, fixed-tick и Worker остаются отдельными этапами.
