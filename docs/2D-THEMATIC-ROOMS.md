# DNG Codex — тематические комнаты

## Цель

Одна система связывает прогрессию этажа, поверхности подземелья, атмосферу,
архетипы комнат и тематические варианты сундуков. Игровые правила ссылаются
только на стабильные ID; пути к PNG остаются в визуальных каталогах.

## Четыре контракта

### `DungeonTheme`

Файл: `tools/dcss-rpg-room-plans.js`.

Тема выбирается по глубине и задаёт:

- `surfaceSetId` для пола и стен;
- `atmosphereId` для света, тумана и частиц;
- `chestSkinIds` — только совместимые с темой сундуки;
- `roomArchetypeIds` — допустимые фоновые комнаты.

`FLOORS_PER_CHAPTER` является общей границей для темы и `floorScaling`.

### `RoomArchetype`

Архетип описывает назначение комнаты, а не её картинку:

- стабильный `id` и роль;
- глубина, вес и пространственные требования;
- `environmentThemeIds` для каждого подземелья;
- сериализуемый `content` без функций;
- варианты и множители бюджетов опасности/награды.

Не реализованные системы остаются `implemented: false` и никогда не попадают в
генерацию. `merchant-alcove` уже показывает контракт будущего торговца.

### `RoomPlan`

Каждый сгенерированный этаж получает ровно один план на комнату:

- `room-N-I`;
- `dungeonThemeId`, `surfaceSetId`;
- `archetypeId`, `variantId`, `environmentThemeId`;
- `chestSkinId` при наличии сундука;
- `dangerBudget`, `rewardBudget`.

План является детерминированными данными. Рендер, декор и сундуки потребляют
его, но не принимают игровых решений.

### `RoomEncounter`

Файл: `tools/dcss-rpg-room-content.js`.

Отдельный проход превращает абстрактный `RoomPlan` в конкретных актёров,
ловушки и точки активации. Он не добавляет скрытую сложность: существующие
бюджеты монстров и событий перераспределяются внутрь особой комнаты.

Сейчас сокровищница поддерживает:

- `unguarded` — безопасный сундук;
- `guarded` — охрана должна быть побеждена до взаимодействия;
- `trapped` — механизм сундука и реальная ловушка на полу;
- `cursed` — урон и статус `poison` либо `chilled`;
- `mimic` — скрытый враг появляется после открытия, награда выдаётся за победу;
- `ambush` и `treasure-cache` — содержимое активируется дверью комнаты.

В encounter хранятся стабильные ссылки `monsterIds`, `trapEventIds`,
`rewardLootIds`, `findId` и `surpriseId`. Рендер не проверяет тип комнаты.

## Как добавить новую комнату

1. Добавить одну запись в `ROOM_ARCHETYPE_CATALOG`.
2. Указать допустимые темы окружения и варианты.
3. Пока логика не готова, оставить `implemented: false`.
4. Добавить материализацию в `dcss-rpg-room-content.js`, используя стабильный
   hash/RNG-поток из `seed + roomId + system salt`.
5. Включить архетип в `DungeonTheme.roomArchetypeIds` или назначать его по
   семантическому содержимому.
6. Добавить save-команды для изменяемого состояния, но не сохранять PNG-пути.
7. Прогнать seed-sweep: связность, отсутствие пересечений, соблюдение бюджета и
   соответствие ассетов теме.

## Будущий торговец

Для торговца не требуется отдельная ветка генератора уровня. Нужно:

- реализовать NPC `merchant` со стабильным instance ID;
- добавить команду взаимодействия `trade`;
- создать data-driven ассортимент по `rewardBudget` и глубине;
- сохранять только купленные позиции/валюту/состояние NPC;
- переключить `merchant-alcove.implemented` в `true` и добавить его в нужные
  `DungeonTheme`.

Так торговец автоматически получит стены, свет, декор и будущие тематические
варианты своего подземелья.

## Запрещённые сокращения

- Не выбирать текстуры непосредственно внутри генератора комнаты.
- Не использовать `Math.random()` или общий mutable RNG.
- Не сохранять asset paths в save.
- Не добавлять `if (room === merchant)` в общий renderer.
- Не разрешать неполный тематический пакет без явного fallback и теста.
