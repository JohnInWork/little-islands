# DNG Codex — торговцы

## Игровая роль

Торговец — спокойная передышка и способ превратить неподходящую находку в
следующее решение билда. На III, VI и IX этажах тематическая комната получает
одного из трёх торговцев: бронника, реликварий или снабженца. Ассортимент из
4–6 позиций детерминирован seed, глубиной, комнатой и вариантом NPC.

Неизвестная аркана не раскрывается ценой: все неопознанные предметы одной семьи
оцениваются одинаково. PNG, локализованное имя и состояние окна не участвуют в
игровом расчёте.

## Экономика

Единый профиль находится в `MERCHANT_ECONOMY`:

| Операция | Множитель |
| --- | ---: |
| Покупка исходного товара | `1.00` |
| Продажа игроком | `0.34` |
| Обратный выкуп | `0.68` |

У торговца конечный кошелёк: `60 + 18 × depth + seeded 0…16` золота. Продажа
невозможна, если NPC не может заплатить. Обратный выкуп всегда дороже полученной
при продаже суммы, поэтому торговый цикл не создаёт золото. Одновременно
торговец хранит не больше восьми проданных игроком позиций.

## Постоянное состояние

`run.floor.merchants` содержит по одной записи на сгенерированного NPC:

```js
{
  merchantId,
  gold,
  purchasedEntryIds,
  buyback: [{ record, price }]
}
```

`purchasedEntryIds` не даёт исходному товару появиться снова после reload.
`buyback` владеет точной записью проданного предмета, включая UID, аффиксы,
артефактную силу, проклятие и stack. Один UID может принадлежать либо герою,
либо сундуку, либо торговцу; save-валидация отвергает двойное владение.

## Команды и события

Правила находятся в `tools/dcss-rpg-merchant.js` и не знают о DOM:

- `merchant-buy` → `merchant-item-bought`;
- `merchant-sell` → `merchant-item-sold`;
- `merchant-buyback` → `merchant-item-bought-back`.

Каждая функция сначала проверяет команду, кошельки, вместимость рюкзака,
состояние товара и владельца UID. При отказе ни один массив и ни один кошелёк не
меняется. `tools/dcss.js` только создаёт команду, применяет подтверждённый state,
показывает событие и сохраняет забег.

## UI и локализация

Окно показывает оба кошелька, вкладки покупки и продажи, цену каждой операции и
явную метку обратного выкупа. Все подписи имеют RU/EN-вариант. Кнопки остаются
крупными и доступными большому пальцу; закрытие находится в нижней зоне.

## Save v35

Ключ — `dng-codex:rpg:v35`, рядом хранится last-good backup. Миграция v33
проверяет старый список купленных позиций, создаёт кошелёк NPC, переносит
проданный исходный ассортимент и начинает с пустого обратного выкупа. Старые
версии проходят существующие миграции, затем получают новое состояние торговца.

## Как расширять

1. Новый тип торговца добавлять в `MERCHANT_VARIANTS`, не в UI.
2. Ассортимент фильтровать данными предмета и глубиной; не хранить пути к ассетам.
3. Новую операцию оформлять отдельной чистой командой и доменным событием.
4. Новое сохраняемое поле требует версии, миграции и corrupt-теста.
5. Проверять покупку, продажу, reload, нехватку золота, полный рюкзак, пустой
   кошелёк NPC и уникальность UID.

Основные проверки: `tests/dcss-rpg-merchant.test.js`,
`tests/dcss-rpg-core.test.js`, `tests/dcss-rpg-ui.test.js` и `npm run check`.
