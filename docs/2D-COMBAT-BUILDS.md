# 2D RPG — оружие и боевые сборки

> Локальная поставка T07 от 13.09.2026. Оружие уже меняет способ боя, экипировка
> формирует скорость героя, а противники имеют собственные профили угрозы.

## Контракт данных

Боевые параметры оружия хранятся только в `tools/dcss-rpg-content.js`:

```js
combat: {
  style: 'spear',
  range: 2,
  cooldown: 0.84,
  attackDuration: 0.36,
  damageScale: 1,
  projectile: 'arcane',      // только для дальнего оружия
  projectileSpeed: 6,        // клеток в секунду
}
```

- `style` выбирает правило дистанции и визуальный жест;
- `range` измеряется в клетках;
- `cooldown` задаёт реальный темп автоатаки;
- `attackDuration` задаёт длительность читаемой анимации;
- `damageScale` умножает итоговую атаку героя;
- `projectile` и `projectileSpeed` включают настоящий летящий объект.

Вторая рука может содержать `combat: { guard: 1 }`. Защита щитом работает только
вместе с клинком: копьё, посох и тяжёлое оружие не получают скрытый блок от
оставшегося в слоте предмета. Формулы и допустимые профили находятся в
`tools/dcss-rpg-rules.js`; renderer не решает, можно ли атаковать.

Любая экипировка может менять пять реальных характеристик: `attack`, `defense`,
`maxHp`, `moveSpeed` и `attackSpeed`. Последние две хранятся как относительные
модификаторы: `0.14` означает +14%, `-0.12` — −12%. Скорость движения умножает
базовые 2.85 клетки/с, а скорость атаки сокращает cooldown и анимацию замаха.
Тяжёлая броня и оружие могут давать отрицательные модификаторы — сила имеет цену.

## Профили угрозы монстров

У каждого монстра в каталоге есть собственный блок `threat`:

```js
threat: {
  attackRate: 1.3, // атак в секунду
  vision: 7,       // дальность обнаружения в клетках
  windup: 0.14,    // честное окно до получения урона
  pursuit: 6,      // сколько секунд помнит героя за углом
}
```

Вместе с индивидуальными `hp`, `damage` и `speed` это отличает охотников от
тяжёлых противников. Глубина ускоряет движение и атаки, расширяет зрение и память,
слегка сокращает замах. После обнаружения враг продолжает погоню за углом, но урон
приходит только после пиксельного телеграфа и только если герой всё ещё рядом.

## Уже различающиеся стили

| Стиль | Правило | Игровое ощущение |
|---|---|---|
| Клинок + щит | соседняя клетка; быстрый/средний удар; щит снижает входящий урон | надёжный ближний бой |
| Копьё | одна прямая линия до 2 клеток; стена и диагональ запрещают удар | держит проход и дистанцию |
| Посох | цель до 4,5 клеток и только по прямой видимости; выпускает снаряд | дальний бой с позиционированием |
| Тяжёлое | соседняя клетка; медленнее, но высокий множитель урона | рискованный сильный удар |
| Лук | дальность 5 и летящая стрела | подготовлен в данных и runtime |

В активной игре вручную проверены клинок, копьё и посох. Тяжёлое оружие и лук
используют тот же контракт, но отдельная балансная проверка этих сборок ещё нужна.

## Runtime-поток

1. `currentHeroCombat()` получает профиль надетых рук.
2. `canWeaponAttack()` проверяет клетки, дистанцию, стены и LOS.
3. При захвате цели герой отменяет маршрут и начинает соответствующий жест.
4. Ближний/дальний по древку урон применяется через `damageMonster()`; посох и лук
   создают projectile с зафиксированным уроном.
5. Исчезнувшая цель, истёкшее время или потеря LOS уничтожают projectile без урона.
6. HUD показывает знак стиля и блок/дальность; карточка оружия — дальность и три
   дискретных деления темпа. Игроку не требуется читать описание во время боя.

## Инварианты для следующих моделей

- Новое оружие не добавлять условием по `id` в `tools/dcss.js`: достаточно записи
  `combat` и существующего визуального варианта.
- `range`, `cooldown`, `attackDuration` и `damageScale` всегда конечные и больше нуля.
- Projectile не проходит через стену и не переносит урон на новую цель.
- Копьё не бьёт по диагонали или сквозь непроходимую клетку.
- Щит не изменяет исходящий урон; `guard` участвует только в `mitigateDamage()`.
- Боевая конфигурация выводится из предметов; save v4 добавляет только независимые
  слоты плаща, перчаток и пояса и мигрирует v3 без потери прежних вещей.
- Новому стилю нужны: чистое правило, каталог, визуальный телеграф, HUD-знак,
  unit-тест и мобильный браузерный кадр.

Проверки: `tests/dcss-rpg-rules.test.js`, `tests/dcss-rpg-ui.test.js`, затем
единый шлюз `npm run check`.
