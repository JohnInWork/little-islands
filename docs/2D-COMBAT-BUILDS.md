# 2D RPG — оружие и боевые сборки

> Локальная поставка T07 от 13.09.2026. Оружие уже меняет способ боя, экипировка
> формирует скорость героя, а противники имеют собственные профили угрозы.

## Контракт данных

Боевые параметры оружия хранятся только в `tools/dcss-rpg-content.js`:

```js
combat: {
  style: 'spear',
  range: 2,
  cooldown: 0.84,
  attackDuration: 0.36,
  damageScale: 1,
  projectile: 'arcane',      // только для дальнего оружия
  projectileSpeed: 6,        // клеток в секунду
}
hands: 2,                    // только если оружие занимает обе руки
weaponFamily: 'spear',       // стабильное семейство для специализаций
```

- `style` выбирает правило дистанции и визуальный жест;
- `range` измеряется в клетках;
- `cooldown` задаёт реальный темп автоатаки;
- `attackDuration` задаёт длительность читаемой анимации;
- `damageScale` умножает итоговую атаку героя;
- `projectile` и `projectileSpeed` включают настоящий летящий объект.
- `weaponFamily` связывает предмет с навыком без проверки конкретного `id`.

Одноручное оружие имеет `hands: 1` и может находиться в `hand1` или `hand2`.
Режим боя выводится из двух предметов универсально: одно оружие, оружие со щитом,
два оружия либо двуручное. Щит содержит `offhandKind: 'shield'` и
`combat: { guard: 1 }`; защита работает с любым одноручным семейством. Второе
оружие наносит дополнительный удар с 45% своего боевого множителя и не даёт
`guard`.
`hands: 2` атомарно освобождает обе руки и возвращает
щит, книгу или факел в рюкзак; если двум снятым предметам не хватает места,
команда не меняет состояние. При попытке надеть вторую руку двуручное оружие,
наоборот, снимается. Формулы и допустимые профили находятся в
`tools/dcss-rpg-rules.js`; renderer только скрывает защитный off-hand слой.

Любая экипировка может менять пять реальных характеристик: `attack`, `defense`,
`maxHp`, `moveSpeed` и `attackSpeed`. Последние две хранятся как относительные
модификаторы: `0.14` означает +14%, `-0.12` — −12%. Скорость движения умножает
базовые 2.85 клетки/с, а скорость атаки сокращает cooldown и анимацию замаха.
Тяжёлая броня и оружие могут давать отрицательные модификаторы — сила имеет цену.

## Профили угрозы монстров

У каждого монстра в каталоге есть собственный блок `threat`:

```js
threat: {
  attackRate: 1.3, // атак в секунду
  vision: 7,       // дальность обнаружения в клетках
  windup: 0.14,    // честное окно до получения урона
  pursuit: 6,      // сколько секунд помнит героя за углом
}
```

Вместе с индивидуальными `hp`, `damage` и `speed` это отличает охотников от
тяжёлых противников. Глубина ускоряет движение и атаки, расширяет зрение и память,
слегка сокращает замах. После обнаружения враг продолжает погоню за углом, но урон
приходит только после пиксельного телеграфа и только если герой всё ещё рядом.

## Уже различающиеся стили

| Стиль | Правило | Игровое ощущение |
|---|---|---|
| Одноручное без второй руки | основной профиль оружия без дополнительного правила | чистая базовая сборка и свободный слот |
| Клинок + щит | соседняя клетка; быстрый/средний удар; щит снижает входящий урон | надёжный ближний бой |
| Два одноручных оружия | основной удар и один дополнительный удар второй рукой | постоянный урон ценой щита |
| Меч любого хвата | серия по одной цели; 4-й/3-й/2-й удар получает +40%/+60%/+80% | ритм и выбор между продолжением боя и сменой цели |
| Одноручный топор + щит | быстрый лёгкий замах; одна дополнительная цель на 25%/40%/55% | защищённый боец против небольшой группы |
| Двуручный топор | медленный тяжёлый замах; 35%/60% по одной дополнительной цели, затем 80% по двум | разрушитель толпы без щита |
| Двуручное копьё | одна прямая линия до 2 клеток; стена и диагональ запрещают удар | держит проход и дистанцию ценой щита |
| Двуручный посох | цель до 4,5 клеток и только по прямой видимости; выпускает снаряд | дальний бой с позиционированием |
| Двуручное тяжёлое | соседняя клетка; медленнее, но высокий множитель урона | рискованный сильный удар без второй руки |
| Двуручный лук | дальность 5 и летящая стрела | дальность вместо защиты второй руки |

В активной игре вручную проверены клинок, копьё и посох. Тяжёлое оружие и лук
используют тот же контракт, но отдельная балансная проверка этих сборок ещё нужна.

Топоры — первая законченная специализация. `weaponFamily: 'axe'` и изученные
Топоры I/II/III включают детерминированный широкий удар. `hands: 1` получает
лёгкий профиль 25%/40%/55% по одной соседней цели; `hands: 2` — 35%/60% по одной,
а на III ранге две цели по 80%. Чистый выбор целей
в `dcss-rpg-cleave.js` ограничен передней полусферой, соседством с основной целью
и LOS. Пассивная фауна не входит в список кандидатов.

`war-axe` является одноручным: `blade`-анимация, средний урон, ускоренный темп и
активная защита второй руки. `executioner-axe` остаётся двуручным `heavy`:
медленный высокий урон, широкий след, сильнее hit-stop и прерывание замаха врага.
Новые топоры наследуют один из этих профилей через `hands`, без проверки ID.

Мечи — вторая законченная специализация. `weaponFamily: 'sword'` включает один
ритм на полный цикл автоатаки: I/II/III ранг усиливает каждый 4-й/3-й/2-й
состоявшийся удар по той же цели на 40%/60%/80%. Отменённый замах не продвигает
серию, смена цели или конкретного клинка начинает её заново, а обычное движение
вокруг текущего врага не влияет на счётчик. При двух клинках ритм принадлежит
основной руке и растёт один раз за цикл; если меч только во второй руке, он сам
получает усиленный удар. Состояние серии временное и не входит в save.

Пул мечей теперь охватывает быстрые одноручные `duelist-rapier` и
`iron-falchion`, сбалансированный `long-sword`, тяжёлый двуручный
`dungeon-greatsword` и редкий `sword-of-power`. Каждый имеет отдельные иконку,
слой на герое, темп, урон и глубину выпадения.

Изученный «Щит» добавляет активному off-hand 15%/25%/35% полного блока.
На III ранге блок оглушает ударившего врага на 0,6 секунды, но никогда не двигает
его клетку. Бросок воспроизводим по seed и номеру атаки; двуручные сборки не могут
получить эффект, потому что их `guard` равен нулю.

## Runtime-поток

1. `resolveWeaponLoadout()` определяет универсальный хват, а
   `currentHeroCombat()` получает профиль надетых рук.
2. `canWeaponAttack()` проверяет клетки, дистанцию, стены и LOS.
3. При захвате цели герой отменяет маршрут и начинает соответствующий жест.
4. Ближний/дальний по древку урон применяется через `damageMonster()`; при двух
   оружиях контакт добавляет ровно один ограниченный удар второй рукой. Посох и
   лук создают projectile с зафиксированным уроном.
5. `resolveSwordRhythmStrike()` продвигает серию только в момент реального контакта
   и возвращает уже рассчитанный усиленный урон.
6. Исчезнувшая цель, истёкшее время или потеря LOS уничтожают projectile без урона.
7. HUD показывает знак стиля и блок/дальность; карточка оружия — дальность и три
   дискретных деления темпа. Игроку не требуется читать описание во время боя.

## Инварианты для следующих моделей

- Новое оружие не добавлять условием по `id` в `tools/dcss.js`: достаточно записи
  `combat`, допустимого `weaponFamily` и существующего визуального варианта.
- `range`, `cooldown`, `attackDuration` и `damageScale` всегда конечные и больше нуля.
- Projectile не проходит через стену и не переносит урон на новую цель.
- Копьё не бьёт по диагонали или сквозь непроходимую клетку.
- Щит не изменяет исходящий урон; `guard` участвует только в `mitigateDamage()`.
- Любое оружие с `hands: 1` допустимо в любой руке; `hands: 2` — только в основной.
- Хват определяется общим правилом, а не `id`, классом или семейством оружия.
- Дополнительный удар второй рукой не должен порождать рекурсивную цепочку атак.
- Два меча не должны продвигать ритм дважды за один цикл автоатаки.
- Не дублировать один UID оружия в двух слотах.
- Боевая конфигурация выводится из предметов; save v4 добавляет только независимые
  слоты плаща, перчаток и пояса и мигрирует v3 без потери прежних вещей.
- Новому стилю нужны: чистое правило, каталог, визуальный телеграф, HUD-знак,
  unit-тест и мобильный браузерный кадр.

Проверки: `tests/dcss-rpg-rules.test.js`, `tests/dcss-rpg-ui.test.js`, затем
единый шлюз `npm run check`.
