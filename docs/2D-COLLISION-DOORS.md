# DNG Codex — коллизии актёров и двери

Эта часть текущей 2D-игры использует существующие координаты, генерацию и save v11.
Отдельного физического движка или новой схемы сохранения не добавлено.

## Движение и контакт

Источник правил: [dcss-rpg-actor-collision.js](../tools/dcss-rpg-actor-collision.js).
Позиции актёров и целей — в пикселях мира; размер клетки передаётся явно.

- `blockingActorCells(actors, tileSize)` резервирует текущую клетку живого
  существа и только ближайший шаг `wanderTarget`, `route[0]` либо `path[0]`.
  Строка `path` у фауны — URL спрайта, не маршрут. Дальняя часть пути не
  резервируется навсегда; мёртвый актёр освобождает клетки.
- `constrainActorMovement({actor, next, blockers, tileSize})` проверяет весь
  отрезок движения, не только конечную точку. Возвращает допустимые `x/y` и
  `blocked`, не меняя входные объекты. Минимальная дистанция общая с толпой
  монстров: `MONSTER_MIN_SEPARATION * tileSize`. Герой, враги и фауна не могут
  проскочить друг сквозь друга за большой шаг кадра.
- Уже пересекавшиеся актёры старого сохранения могут постепенно расходиться,
  но не двигаться глубже друг в друга и не телепортируются в соседнюю клетку.
- `canActorsMeleeContact()` использует один порог начала и контакта обычной
  ближней атаки: `1.15 * tileSize`, с проверкой проходимости/углов. Если герой
  вышел из радиуса во время замаха, удар не попадает. Копьё и снаряды продолжают
  использовать отдельные дальность/LOS из профиля оружия.
- `meleeApproachPoint()` закрывает небольшой зазор между актёрами в соседних
  клетках, оставаясь внутри собственной клетки. Это устраняет остановку перед
  врагом, когда grid-путь уже пуст, но расстояния для удара ещё недостаточно.

Связывание — в `tools/dcss.js`: `findPath`, `requestHeroMove`, `commitHeroPath`,
`updateHero`, `updateWorld`, `updatePassiveCreatures`.

Автоматический путь героя обходит живую занятость; нельзя тапом назначить
занятую клетку исключением. В узком коридоре путь ждёт/останавливается, в комнате
может найти обход. Вражеский путь использует собственную занятость и не узнаёт
скрытые ловушки из знаний героя. Динамически закрытая дверь отменяет старый шаг.

Новый допустимый приказ движения отменяет прежний замах и владеет героем до
окончания маршрута или препятствия. Автобой не стирает отход после одного
маленького шага. Повторный ввод в уже занятую клетку без нового пути не отменяет
замах бесконечно: столкновение останавливает движение, но оставляет возможность
сражаться. При подходе к соседнему врагу разрешено сокращение зазора внутри
своей клетки с той же непрерывной проверкой коллизии.

## Дверь остаётся объектом

Закрытая и открытая дверь сохраняются в `dungeon.doors` / `doorDefinitions`.
Открывание не удаляет её определение. WebGL-сборка хранит петлю и видимую створку,
поворачивающуюся на 90°; открытая дверь по-прежнему отбрасывает тень. При загрузке
она сразу принимает сохранённую конечную позу без вспышки закрытого состояния.

Тап по самой видимой створке переключает «Открыть дверь» / «Закрыть дверь»;
клавиши E/Space используют ту же команду. Издалека первый тап ведёт к ближайшему
подходу, рядом следующий тап взаимодействует. Отдельной HUD-кнопки и белого
маркера для двери нет. Открывать можно соседнюю разведанную дверь; повторный ввод
не прерывает уже начатую анимацию. Пауза, смерть и удалённая/неизвестная цель
отклоняют действие.

Правило закрывания: [dcss-rpg-doors.js](../tools/dcss-rpg-doors.js),
`canCloseDoor({door, actors, tileSize})`.

- `door.x/y` — целые grid-координаты; `actors` включает героя, живых монстров
  и фауну с мировыми координатами.
- Нельзя закрыть проём, если тело пересекает его границу или ближайший шаг
  направлен внутрь. Центр ещё вне дверной клетки не означает свободный проём.
- Дальние запланированные шаги не блокируют дверь. Мёртвые тела не мешают;
  неоднозначная нечисловая живая позиция заставляет отклонить закрывание.
- Запрос не сдвигает актёров и не отменяет их пути. При отказе runtime сообщает
  «Проём занят»; состояние двери и сохранение не меняются.

В `beginDoorTransition()` закрывание сразу резервирует пустой проход как `D`,
чтобы никто не вошёл во время анимации. Открывание остаётся непроходимым до
конца. `updateDoorOpening()` меняет сохранённое состояние только при завершении;
при смерти возвращает прежнюю проходимость и позу. Команда сбрасывает прежнее
согласие наступить на ловушку. После открывания заново проверяются обзор и Чутьё.

## Сохранение: не смешивать открытие и награду

- `floor.opened` — двери, открытые **сейчас**. Закрывание убирает ID, повторное
  открывание возвращает его; это не журнал всех когда-либо открытых дверей.
- `floor.triggered` — уже сработавшие одноразовые сюрпризы. Закрывание не
  удаляет эту запись. Цикл открыть → закрыть → открыть не повторяет засаду/награду.
- Save остаётся v11: существующие поля достаточны. Перегенерация этажа и
  сброс прогресса не требуются.
- Сохранённая позиция монстра/фауны — смещение центра клетки:
  `worldX = (savedX + 0.5) * tileSize`, аналогично Y. Гидратация проверяет
  `floor(savedX + 0.5)` / `floor(savedY + 0.5)`. Проверка `floor(savedX)` ошибочно
  помещала свободное тело возле порога внутрь закрытой двери. Не менять сами
  сохранённые координаты для обхода этого дефекта.

## Рецепт безопасного расширения

1. Для нового актёра определить его world-позицию, `dead` и ближайшую цель;
   включить в общий blocker-набор без копирования отдельной формулы радиуса.
2. Для нового вида двери сохранить стабильный ID и разделение
   `opened`/`triggered`; геометрия лишь отображает проверенное состояние.
3. Новое действие проверять общей командой до изменения мира. Не проталкивать
   тело из проёма и не отменять чужой маршрут, чтобы искусственно разрешить закрытие.
4. Изменяя дальность удара, согласовать начало/кадр контакта и подход в соседней
   клетке. Не расширять радиус попадания как обход ошибки движения.
5. Проверить целевые тесты, затем реальный ввод и `npm run check`. Урон, путь,
   проходимость и поза после reload должны совпадать, а не только выглядеть верно.

Тесты: `dcss-rpg-hero-collision.test.js` — sweep, занятость, подход/отход и бой;
`dcss-rpg-door-state.test.js` — тело/ближайший шаг, обе оси створки, save и
пограничные координаты; `dcss-rpg-door-runtime.test.js` — настоящие команды,
цикл состояний, пауза, смерть и однократный сюрприз. Фактические браузерные
сценарии и ограничения записываются в [VERIFICATION.md](VERIFICATION.md).
