# DNG Codex — постоянные сундуки

Сундук — не мгновенная награда, а настоящий контейнер этажа. После успешного
открытия игра показывает содержимое сундука и рюкзака, позволяет одним нажатием
переносить предметы в обе стороны и отдельно забрать золото. Закрытый экран можно
снова открыть у того же сундука; состояние переживает autosave и reload.

## Контракт состояния

`run.items` и `run.inventory` содержат только принадлежащие герою предметы.
Предметы вне героя хранятся отдельно в `floor.chests`:

```js
{
  findId: 'find-2-6',
  opened: true,
  destroyed: false,
  gold: 14,
  items: [{ id: 'long-sword', uid: 'chest-2-6-0', affixIds: [] }],
}
```

- `findId` ссылается на единственный `sealed-cache` сгенерированного этажа.
- Содержимое определяется seed, глубиной и `lootAbundance` при создании этажа,
  затем сохраняется как данные и больше не перебрасывается при открытии.
- UID уникальны между героем и всеми контейнерами. Один предмет одновременно
  принадлежит ровно одному месту.
- Ёмкость сундука — 8 разных записей, рюкзака — 12. Одинаковые расходники
  объединяются в стек без занятия новой ячейки.
- Разбитый сундук сохраняет доступ к уцелевшему содержимому, но больше не
  принимает предметы. Мимик уничтожает контейнер и становится отдельным врагом.

## Команды

Чистый модуль `tools/dcss-rpg-chest-containers.js` принимает транспортные команды
`chest-take`, `chest-store`, `chest-take-gold` и возвращает `{ ok, state, events }`.
Он не импортирует DOM, Canvas, Three.js и не мутирует входные массивы. Runtime
только применяет принятый снимок, показывает эффект и сохраняет забег. Это та же
граница, которую позже можно перенести в Worker или авторитетный сервер.

Первичное открытие, ключ, взлом, ловушка, проклятие и мимик остаются в
`dcss-rpg-chests.js`. Успешное действие переводит контейнер в `opened`; золото не
начисляется автоматически. `smash` оставляет примерно половину содержимого и
золота. Повторный подход предлагает `browse`, а не повторяет награду или ловушку.

## UI

Окно содержит две вертикально прокручиваемые области: сундук сверху и рюкзак
снизу в портрете, рядом друг с другом в альбоме. Имя, редкость, главный эффект и
иконка используют тот же безопасный RU/EN-presenter, что рюкзак. Кнопка закрытия
находится снизу; `Escape` и focus trap поддерживаются. На игровой сцене нет
новой постоянной рамки или маркера.

## Save v35

Ключ текущего снимка — `dng-codex:rpg:v35`, рядом хранится last-good backup.
Миграция v32→v33 создаёт содержимое ещё не использованного сундука. Уже разрешённый
старый сундук становится открытым и пустым, чтобы обновление никогда не выдало
награду второй раз. Гидратация сверяет точный список `findId`, форму предметов и
отсутствие двойного владения UID.

## Расширение

Чтобы добавить новый тип постоянного хранилища, не нужно менять `run.items`.
Следует добавить отдельное floor-состояние, чистые команды переноса и миграцию.
Если сундуку нужна новая тематическая таблица добычи, она выбирается при создании
контейнера из данных комнаты; открытие не должно использовать случайность.
