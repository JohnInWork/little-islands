# DNG Codex — автоматические описания предметов

Описание предмета не пишется вручную. Его строит
`tools/dcss-rpg-item-description.js` из тех же данных, которые использует игра:
типа предмета, хвата, характеристик, боевого профиля, магических свойств и
эффекта применения.

Пример входных данных:

```js
{
  id: 'frost-gloves',
  slot: 'gloves',
  stats: { attack: 2, moveSpeed: 0.07 },
  magic: { immunity: ['chilled'] }
}
```

Результат:

- RU: `Перчатки · Иммунитет: Озноб · +2 атака · +7% движение`
- EN: `Gloves · Immunity: Chilled · +2 attack · +7% move speed`

У карточки есть одна короткая строка `summary` и массив атомарных `facts`.
Список, подробная карточка и уведомления обязаны использовать эту общую модель,
а не собирать собственный текст.

## Какие поля понимает генератор

- `slot`, `kind`, `weaponFamily`, `hands` — тип и хват;
- `stats` — числовые модификаторы;
- `combat` — дальность, темп, снаряд или блок;
- `magic` — реально подключённые постоянные свойства;
- `artifactPowerId`, `artifactCurseId` — большая сила и явный недостаток;
- `useEffect`, `potionEffect` — результат применения;
- `interactionResource`, `placeableTrap`, `gold` — утилитарное действие.

Малые свойства сначала объединяет `materializeItemAffixes()`, затем
`materializeProceduralArtifact()` добавляет одну большую силу и возможный явный
недостаток. Тот же генератор описывает итоговые числа и магию без отдельного
текста для каждого сочетания.

Название остаётся отдельным коротким контентом: предпочтительно
`name: { ru, en }` в записи предмета. Оно не должно содержать свойства или
историю предмета. Старый словарь имён пока сохранён для совместимости каталога.

## Как добавить новое свойство

1. Сначала реализовать игровую механику и её чистое правило.
2. Добавить стабильное поле в данные предмета без проверки конкретного `id`.
3. Добавить одну RU/EN-запись в словарь генератора.
4. Проверить числовое значение, экипировку, снятие, сохранение и оба языка.
5. Только после этого использовать свойство в каталоге предметов.

Полёт, невидимость и вампиризм уже имеют игровые потребители и словарные факты.
Неизвестное поле вроде `magic.timeStop` по-прежнему выбрасывает ошибку, чтобы
интерфейс не обещал неработающую способность.

## Неизвестные предметы

Неопознанное зелье всегда получает нейтральный тип и факт «эффект неизвестен».
Настоящий эффект, редкость и сила не попадают в итоговую модель до опознания.

## Проверка

`tests/dcss-rpg-item-description.test.js` обходит весь каталог на RU/EN,
ограничивает длину краткого описания, проверяет неизвестные зелья, запрещает
устаревшие таблицы лора и подтверждает общий контракт расходуемых предметов с
runtime.
