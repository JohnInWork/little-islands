# DNG Codex — визуальная мастерская

`tools/sprites.html` — локальный редактор соответствий между стабильными
игровыми ID и спрайтами из встроенного набора Dungeon Crawl. Он не создаёт новые
предметы, не меняет характеристики и не записывает ничего в save забега.

## Что можно настраивать

- находки, события, ловушки, дверь, святилище, выход и финальный артефакт;
- иконки всех предметов, включая безопасную внешность неопознанного зелья;
- всех враждебных монстров и пассивных животных;
- масштаб и вертикальную посадку billboard/2D-спрайтов. Для настоящей 3D-двери
  меняется только материал полотна, поэтому геометрические регуляторы выключены.

Слева выбирается реальная сущность игры, в центре виден результат на каменном
полу, справа находится библиотека из 3383 локальных PNG. Фильтр «Подходящие»
ограничивает выдачу совместимым семейством (`item/`, `mon/`, `dngn/traps/` и
так далее); его можно снять, если нужен нестандартный вариант. Поиск понимает
имена файлов и основные русские синонимы.

## Контракт данных

Визуальная настройка хранится отдельно в localStorage по ключу
`dng-codex:visual-overrides:v1`:

```json
{
  "version": 1,
  "bindings": {
    "monster:goblin:world": {
      "path": "mon/orc.png",
      "scale": 1.1,
      "offsetY": -8
    }
  }
}
```

Ключ имеет форму `kind:id:channel`. Разрешены только относительные локальные
PNG-пути, ограниченный масштаб `0.5…2.5` и целое смещение `−40…40`. Документ
строго валидируется при чтении и импорте. Неверный JSON не попадает в runtime.
Экспорт нужен для переноса выбора между браузерами; импорт полностью заменяет
локальный черновик визуальных привязок.

`tools/dcss-rpg-visual-overrides.js` — единственный владелец схемы, проверки и
fallback. `tools/dcss.js` загружает документ один раз при старте, заранее
подгружает использованные пути и разрешает внешний вид перед созданием
рендер-состояния. Для проверки изменения нужно перезагрузить открытую игру.

## Обновление каталога

После добавления или удаления PNG выполнить:

```bash
npm run sprites:manifest
```

Скрипт `scripts/generate-dcss-sprite-manifest.mjs` рекурсивно и
детерминированно пересобирает
`public/assets/dcss-preview/sprite-manifest.json`. `npm run build` делает это
автоматически через `prebuild`.

## Как расширять

1. Добавить сущность со стабильным ID в её игровой каталог.
2. Добавить отображение сущности в массив `entities` мастерской, если семейство
   ещё не строится из каталога автоматически.
3. В runtime вызвать `runtimeVisual(kind, id, channel, fallbackPath, scale,
   offsetY)` в точке создания визуального состояния.
4. Использовать полученные `path`, `scale`, `offsetY` только в renderer. Не
   пропускать их в урон, лут, RNG, коллизии или сохранение забега.
5. Добавить проверку семейства в `tests/dcss-rpg-visual-overrides.test.js` и
   проверить мастерскую в desktop и mobile viewport.
