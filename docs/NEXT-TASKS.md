# DNG Codex — следующие задачи

Здесь только незавершённые проверяемые срезы. Готовые механики описаны в
[START-HERE.md](START-HERE.md), а правила расширения — в
[EXTENDING.md](EXTENDING.md). Одна задача не должна одновременно менять
генерацию, весь баланс и интерфейс.

## 1. Охота, мясо и костёр

**Цель:** связать уже гуляющую пассивную фауну с мягким голодом через честную
цепочку «решение охотиться → бой → добыча → приготовление».

**Минимальный срез:**

- одна крупная контекстная команда `Охотиться / Hunt` рядом с животным;
- атомарный переход конкретного `instanceId` в боевое состояние без случайного
  захвата остальных животных автобоем;
- HP, защита и видовая реакция животного: побег либо ответная атака;
- `raw-meat` появляется только после реальной смерти и только один раз;
- костёр использует общий реестр действий и превращает выбранное количество
  сырого мяса в `cooked-meat` целиком либо ничего;
- приготовленное мясо насыщает через общий `nutrition`, а сырое остаётся
  ингредиентом и товаром;
- состояние охоты, смерти и полученной добычи переживает reload;
- RU/EN, пауза симуляции и удобные цели касания на 390×844 и 844×390.

**Не входит:** приручение, разведение, рецепты из нескольких ингредиентов и
отдельная валюта. Контракт: [2D-HUNGER.md](2D-HUNGER.md).

## 2. Неизвестные свитки и жезлы

**Цель:** расширить рабочую систему неизвестности зелий на два новых семейства,
не раскрывая эффект через имя, иконку, редкость, цену или массовый разбор.

Сначала нужен один свиток и один жезл с реально работающими эффектами. Затем —
seed-зависимые внешности, опознание, применение, заряд/расход и сохранение знания.
Новый эффект сначала реализуется чистым правилом, только потом попадает в каталог.

## 3. Первый выбор приручения

**Цель:** дать уже гуляющим животным одну осмысленную роль без строительства
всей системы выживания сразу.

Первый срез: одно приручаемое существо, один корм, явная команда рядом, один
режим поведения спутника и сохранение владельца. Приручение конкретного
`instanceId` несовместимо с уже начатой охотой; это правило проверяется общей
командой, а не только скрытием кнопки в интерфейсе.

## 4. Второй набор комнатных событий

Добавить 3–4 архетипа из уже принятого направления окружения: алтарная ниша,
могильник, опасный фонтан и читаемая табличка/руна. Каждый объект использует
`INTERACTION_REGISTRY`, не получает постоянной рамки в мире и предлагает
разные действия только если у них есть реальные последствия.

## 5. Следующая глава подземелья

Только после задач 1–4: расширить забег за пределы трёх этажей. Новая глава
должна одновременно получить согласованные поверхности, атмосферу, сундуки,
монстров и веса комнат. Сложность берётся из `floorScaling`, а не из ручных
множителей внутри отдельных врагов.

## Общая приёмка

- стабильные ID и детерминированный RNG;
- атомарная команда: сначала полная проверка, затем одно изменение состояния;
- save version и миграция при каждом новом сохраняемом поле;
- точные RU/EN-строки без обещаний неработающей механики;
- целевые unit/runtime-тесты и затем `npm run check`;
- ручная проверка на телефоне остаётся отдельным обязательным шагом перед показом.
