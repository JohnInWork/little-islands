# DNG Codex — следующие задачи

Здесь только незавершённые проверяемые срезы. Готовые механики описаны в
[START-HERE.md](START-HERE.md), а правила расширения — в
[EXTENDING.md](EXTENDING.md). Одна задача не должна одновременно менять
генерацию, весь баланс и интерфейс.

## 1. Расширить неизвестную аркану

**Цель:** дать уже подключённым семействам больше разных решений, не раскрывая
эффект через имя, иконку, редкость, цену или массовый разбор.

Первый вертикальный срез завершён: работают по одному свитку и жезлу, три исхода
книг, общие seed-внешности, Оценка, расход/заряды и сохранение знаний. Следующий
срез — по одному новому тактическому эффекту свитка и жезла с реальным выбором
цели. Новый эффект сначала реализуется чистым правилом, только потом попадает в
каталог. Контракт: [2D-ARCANA.md](2D-ARCANA.md).

## 2. Первый выбор приручения

**Цель:** дать уже гуляющим животным одну осмысленную роль без строительства
всей системы выживания сразу.

Первый срез: одно приручаемое существо, один корм, явная команда рядом, один
режим поведения спутника и сохранение владельца. Приручение конкретного
`instanceId` несовместимо с уже начатой охотой; это правило проверяется общей
командой, а не только скрытием кнопки в интерфейсе.

## 3. Второй набор комнатных событий

Добавить 3–4 архетипа из уже принятого направления окружения: алтарная ниша,
могильник, опасный фонтан и читаемая табличка/руна. Каждый объект использует
`INTERACTION_REGISTRY`, не получает постоянной рамки в мире и предлагает
разные действия только если у них есть реальные последствия.

## 4. Следующая глава подземелья

Только после задач 1–3: расширить забег за пределы трёх этажей. Новая глава
должна одновременно получить согласованные поверхности, атмосферу, сундуки,
монстров и веса комнат. Сложность берётся из `floorScaling`, а не из ручных
множителей внутри отдельных врагов.

## Общая приёмка

- стабильные ID и детерминированный RNG;
- атомарная команда: сначала полная проверка, затем одно изменение состояния;
- save version и миграция при каждом новом сохраняемом поле;
- точные RU/EN-строки без обещаний неработающей механики;
- целевые unit/runtime-тесты и затем `npm run check`;
- ручная проверка на телефоне остаётся отдельным обязательным шагом перед показом.
