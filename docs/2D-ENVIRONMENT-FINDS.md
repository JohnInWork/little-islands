# DNG Codex — интерактивные находки

Этот срез превращает окружение из декора в короткие решения без отдельного меню.
На каждом этаже есть три находки в разных комнатах:

| ID | Объект | Результат |
| --- | --- | --- |
| `sealed-cache` | древний сундук | обычный/запертый/с ловушкой/проклятый/живой вариант |
| `crystal-vein` | живая кристальная жила | осколки и `power +1` |
| `forgotten-grave` | проклятая гробница | заметный урон и больше осколков |

Игрок касается самой находки. Издалека герой строит путь к ближайшей доступной
соседней клетке; повторный тап рядом открывает общую пиксельную панель действий.
Клавиатура использует `E`/`Space`. Постоянной экранной кнопки взаимодействия нет,
а путь не проходит сквозь объект. Панель ставит мир на паузу и показывает только
команды выбранного объекта.

## Контракт данных

- `FIND_CATALOG` содержит только данные отображения и два языка.
- `createDungeonFinds()` использует отдельный seeded RNG-поток и возвращает
  plain data. Изменения находок не сдвигают комнаты, лут, монстров и двери.
- ID экземпляра имеет формат `find-<depth>-<roomIndex>` и стабилен для этажа.
- Находка ставится внутри не стартовой, не выходной и не surprise-комнаты,
  имеет минимум два подхода и не занимает основной маршрут или другую сущность.
- `dcss-rpg-context-actions.js` содержит единый `INTERACTION_REGISTRY` для
  находок, дверей и ловушек: match, представление и стабильное семейство команд.
- `dcss-rpg-chests.js` независимо от общего RNG определяет тип сундука,
  доступные действия, цену инструмента, урон, шум и награду.
- `resolveFindInteraction()` сначала проверяет живого героя, расстояние,
  актуальное состояние и риск, затем возвращает новый снимок без мутации входа.
- Сундук имеет один из пяти детерминированных типов. Обычный открывается сразу;
  запертый требует ключ, отмычки с навыком либо разрушение; ловушку можно принять
  или обезвредить; проклятие меняет здоровье на повышенную награду; живой сундук
  наказывает неподготовленное открытие. `smash`/`attack` выдают
  `ceil(reward / 2)`, портят остаток и создают шум для ближайших монстров.
- Железный ключ открывает замок любого ранга и расходуется. Взлом I/II/III
  обслуживает замки соответствующего ранга; первый ранг расходует две отмычки,
  последующие — одну. Инструменты нельзя случайно «выпить» из рюкзака.
- Гробница никогда не убивает одним подтверждённым взаимодействием: при
  недостатке HP команда недоступна и прямо объясняет причину.

## Сохранение

Save v14 хранит `floor.resolvedFindIds`. При загрузке каждый ID должен точно
соответствовать находке восстановленного этажа. Миграция v11 добавляет пустой
массив в v12; переход v13 → v14 сохраняет этаж, навыки, инструменты и историю,
не выдавая старому герою новые стартовые предметы задним числом.
Разрешённая находка не выдаёт повторную награду после reload.

## Визуальный язык

Находка остаётся частью пиксельного мира: только billboard-спрайт без цветного
квадрата, напольного ромба или вращающегося указателя. Кристалл даёт ограниченный
локальный свет. После
использования тайник/гробница остаются в мире как след решения, а истощённый
кристалл перестаёт блокировать клетку. Результат сопровождается коротким
RU/EN-toast и цветовым импульсом. Диалог действий появляется только по запросу
и не создаёт постоянной рамки вокруг объекта в мире.

## Расширение

Следующие объекты добавлять записью в `INTERACTION_REGISTRY` и чистой командой,
а не отдельным modal/HUD-скриптом внутри renderer: читаемая табличка,
алтарь-выбор, колодец, редкое логово. Сначала команда и сохранение, затем визуал
и мобильный сценарий. Опасные находки раскрывают точные последствия через
`Осмотреть`; случайность определяется при генерации, а не после нажатия.
